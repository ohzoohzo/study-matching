# 프로필·스터디 해시태그 설계 (2026-10-19)

브랜치: `feat/recruit-hashtags` (기준: `feat/recruit-push`, PR #8 위). 작업 폴더: `study-matching-hashtags` (git worktree).

## 왜 만드나

- 사이트는 지금 한 기수만 쓰는 것처럼 되어 있어요. 소개 영상에서 "우리 기수 전용"이라는 말을 빼기로 했고, 사용자는 **기수를 웹에서 고를 수 있게** 하자고 했어요.
- 처음에는 기수 숫자 목록(1기~30기)을 생각했어요. 사용자가 **프로필 해시태그로, 여러 개, 자유도 높게** 하고 **검색할 때 해시태그로 찾게** 하자고 정했어요(사용자 결정).
- 그래서 기수는 해시태그 가운데 하나예요. 예를 들어 `#프리온보딩7기 #프론트엔드 #주말`처럼 달아요. 어느 부트캠프의 몇 기든, 기수 말고 다른 것이든 사람이 직접 정해요.
- 잘 된 모습: 같은 기수 사람이 `#7기`를 검색하거나 내 태그를 한 번 누르면 우리 기수 스터디만 남아요. 다른 기수 사람도 같은 사이트를 그대로 써요.

## 목표

1. 프로필에 해시태그를 여러 개 달 수 있어요(선택).
2. 스터디를 열 때 해시태그를 달 수 있고, 처음에는 내 프로필 태그가 미리 들어가 있어요.
3. 목록 검색창에서 `#태그`로 찾을 수 있어요. 카드의 태그와 검색창 아래 '내 해시태그' 칩을 누르면 검색어에 넣거나 빼요.
4. 모집자는 신청 목록에서 신청자의 프로필 태그를 봐요.

## 하지 않는 것

- 기수 숫자 목록, 기수 필수 입력은 없애요(사용자 결정).
- 이미 연 스터디의 태그를 나중에 고치는 기능은 없어요. 지금은 스터디 자체를 고치는 기능이 없어요.
- 태그별 페이지·주소(`#/tag/...`), 운영진의 태그 관리·삭제, 신청에 태그 달기는 하지 않아요.
- 태그가 다르다고 신청을 막지 않아요. 다른 태그 스터디도 신청할 수 있고, 받을지는 모집자가 정해요.
- Upstash Redis의 이미 있는 데이터를 고치지 않아요(마이그레이션 없음).

## 하면 안 되는 것 (기능은 돌아가도 실패)

- 태그를 안 달면 스터디를 열거나 신청할 수 없게 막는 것.
- 검색창에 칠 때 화면 전체를 다시 그려서 글자나 포커스가 날아가는 것. 지금처럼 목록과 개수만 바꿔야 해요.
- 태그가 많을 때 375px 카드나 폼이 가로로 넘치는 것.
- `#7기`와 `#7 기`, `#React`와 `#react`가 서로 다른 태그로 갈라지는 것.

## 정한 것

### 데이터

- 사람: `{ id, name, role, tags }`. 스터디: 지금 필드에 `tags`를 더해요. 둘 다 **`#` 없이** 저장해요. 예: `["프리온보딩7기", "React"]`.
- `tags`가 없는 예전 프로필·스터디는 `[]`로 봐요. 저장소 키와 모양(`recruit:<환경>:people`, `studies`)은 그대로예요.
- 스터디 태그는 프로필 태그와 따로 저장해요. 나중에 프로필을 고쳐도 이미 연 스터디의 태그는 그대로예요(제 판단).
- 태그는 공개 목록(`/api/recruit/state`)에 나와요. 카드와 신청 목록에 보여 주려고 다는 것이라 괜찮아요. 개인정보처리방침의 저장 항목에 '해시태그(선택)'를 더해요.

### 규칙 (`recruit/recruit-logic.js`에만 둬요)

- `MAX_TAGS = 10`(한 프로필·한 스터디), `TAG_MAX_LEN = 20`(태그 하나, `#` 빼고).
- **다듬기** `normalizeTag(raw)`: 문자열로 바꾸고 NFC, 앞뒤 공백을 지워요. 앞에 붙은 `#`·`＃`(전각)도 몇 개든 지우고, 안쪽 공백은 모두 지워요. 대소문자는 적은 그대로 둬요.
- **같은 태그인지** `tagKey(tag)`: 다듬은 값을 소문자로 바꿔요. 중복 판단과 검색은 이 값으로 해요.
- **정리** `cleanTags(list)`: 하나씩 다듬고 빈 것은 빼요. `tagKey`가 같으면 먼저 적은 것만 남기고 순서는 지켜요.
- **검사** `validateTags(list)`: 틀리면 이유, 맞으면 `""`를 돌려줘요. `validateTimes`와 같은 모양이고 서버도 써요.
  - 배열이 아니거나 문자열이 아닌 것이 있으면: "해시태그를 다시 확인해 주세요."
  - 정리한 뒤 10개가 넘으면: "해시태그는 10개까지 달 수 있어요."
  - 태그가 `^[\p{L}\p{N}_]{1,20}$`(u 플래그)에 맞지 않으면: "해시태그는 글자·숫자·_로 20자까지 적어 주세요." 한글·영문·숫자·밑줄만 되고 이모지와 기호는 안 돼요.
  - `undefined`·`null`은 맞는 것으로 봐요(선택 칸).
- `validateProfile(p)`와 `validateStudy(s, today)`에서 `p.tags`·`s.tags`를 `validateTags`로 검사해요. 틀리면 `e.tags`에 담아요.
- **입력 나누기** `parseTagInput(text)`: 입력칸에 친 글자를 **쉼표와 `#`(`＃`)에서** 나눠 다듬은 태그 목록으로 바꿔요. 띄어쓰기로는 나누지 않고, 태그 안의 띄어쓰기는 지워요. 그래서 "프리온보딩 7기"는 `프리온보딩7기` 하나가 되고, "#a, #b c #d"는 `["a","bc","d"]`가 돼요. 이유는 `#7기`와 `#7 기`가 갈라지지 않게 하려는 거예요(제 판단).
- **검색** `matchesSearch(study, people, q)`를 넓혀요.
  - `#`(또는 `＃`)으로 시작하는 낱말은 스터디 태그에서만 찾아요. 어떤 태그의 `tagKey`에 그 낱말의 `tagKey`가 들어 있으면 맞아요. 그래서 `#7기`로 `#프리온보딩7기`도 찾아요(사용자가 동의한 동작).
  - 그래서 `#7기`는 `#17기`도, `#React`는 `#ReactNative`도 찾아요. 칩이나 카드 태그를 누르면 태그 전체(예: `#프리온보딩7기`)가 들어가요. 그러면 한 태그가 다른 태그 안에 통째로 들어 있을 때만 겹쳐요. 이건 받아들이고 따로 막지 않아요(제 판단).
  - `#`만 있는 낱말은 무시해요.
  - `#`이 없는 낱말은 지금처럼 이름·목표·모집자 이름에서 찾고, 스터디 태그에서도 찾아요.
  - 낱말은 지금처럼 모두 맞아야 해요(AND).
  - 모집자의 프로필 태그는 검색하지 않아요. 스터디 태그만 봐요(제 판단).
- **검색어에 태그 넣고 빼기** `toggleTagInQuery(q, tag)`: 검색어 안에 `#tag` 낱말이 있으면(`tagKey` 비교) 빼고, 없으면 끝에 붙여요. `tagInQuery(q, tag)`로 칩의 눌림 상태를 정해요.
- **많이 쓰는 태그** `tagSuggestions(people, studies, { exclude = [], limit = 8 })`: 사람 태그와 취소되지 않은 스터디 태그를 `tagKey`로 세서 많이 쓴 순서로 줘요. 같으면 가나다순이에요. 보여 줄 모양은 처음 나온 모양을 써요. `exclude`에 든 것은 빼요.
- 이 함수들은 모두 같은 입력이면 늘 같은 결과를 줘요.

### 서버 (`api/_lib/recruit.js`)

- `saveMe`
  - `body.tags`가 배열이면 `validateTags`로 검사하고, `cleanTags`로 다듬어 저장해요.
  - `undefined`면 이미 있는 내 태그를 그대로 두고, 없으면 `[]`이에요.
  - 틀리면 400과 `fields.tags`를 돌려줘요. 지금 `invalid(...)` 방식과 같아요.
- `createStudy`
  - `body.tags`를 같은 방식으로 받아요. 없으면 `[]`이에요.
  - `validateStudy`가 `tags`를 검사하고, 저장할 때는 `cleanTags`로 다듬어요.
- 둘 다 알림(`notify`)을 보내지 않는 동작이라 PR #8의 `announce` 방식과 부딪히지 않아요.
- 너무 큰 요청을 막으려고, 다듬기 전 배열이 50개를 넘으면 바로 400을 돌려줘요(제 판단).
- `api/recruit/*.js` 진입 파일은 고치지 않아요. 몸통(body)을 그대로 넘기기 때문이에요.

### 화면 (`recruit/recruit.js`, `index.html`의 `<style>`)

- **해시태그 입력칸** (프로필 폼과 스터디 열기 폼이 함께 써요)
  - 라벨은 "해시태그 (선택)"이에요.
  - 지금 단 태그를 칩으로 보여 주고, 칩마다 빼기 버튼을 둬요. 버튼은 Material `close` SVG이고 `aria-label="#태그 빼기"`예요.
  - 그 옆에 입력칸이 있어요. placeholder는 "#프리온보딩7기처럼 적고 Enter"예요.
  - Enter나 쉼표를 누르면 친 글자를 `parseTagInput`으로 나눠 더해요. 스페이스로는 더하지 않아요. 입력칸이 비어 있을 때 Backspace를 누르면 마지막 태그를 빼요. 입력칸 안의 Enter가 폼 저장으로 이어지지 않게 막아요.
  - 폼을 저장할 때 입력칸에 남은 글자도 더해요.
  - 힌트: "여러 개 달 수 있어요. 10개까지, 글자·숫자·_만 써요."
  - 틀리면 칸 아래 `.err`에 이유를 보여 줘요. 친 글자는 지우지 않아요.
  - 아래에 '많이 쓰는 태그'(`tagSuggestions`, 이미 단 것 제외, 8개) 칩 버튼이 있어요. 누르면 더해져요. 하나도 없으면 이 줄은 보이지 않아요.
  - 태그를 더하거나 뺄 때 폼 전체를 다시 그리지 않아요. 지금 요일 칩처럼 입력칸의 글자와 포커스는 그대로 두고, 칩 줄만 바꿔요. 바뀐 내용은 `aria-live`로 짧게 읽어 줘요. 예: "#프리온보딩7기를 달았어요."
- **프로필**
  - 처음 로그인했을 때의 '이름과 직군 정하기'와 오른쪽 위 '내 프로필' 패널 폼에 이름·직군 아래로 해시태그 칸을 둬요.
  - '내 프로필' 머리의 이름·직군 옆에 지금 태그가 보여요.
  - 오른쪽 위 버튼 글자("이름 · 직군")는 그대로예요. 375px에서 좁기 때문이에요(제 판단).
- **스터디 열기**
  - 해시태그 칸이 '간단 목표' 다음에 있어요.
  - 새 초안을 처음 그릴 때 내 프로필 태그가 미리 들어가요. 고친 뒤에는 덮어쓰지 않아요.
- **스터디 카드 (목록)**
  - 제목 아래에 태그를 3개까지 `#태그` 버튼으로 보여 주고, 넘치면 "+2"처럼 남은 수를 적어요.
  - 태그 버튼을 누르면 검색어에 그 태그를 넣거나 빼요(`toggleTagInQuery`).
  - 지금 카드는 통째로 `<a>`라서 안에 버튼을 넣을 수 없어요. 그래서 카드를 `<article class="card study">`로 바꿔요. 제목 링크의 `::after`가 카드 전체를 덮어 누를 수 있게 하고(지금처럼 카드 어디를 눌러도 상세로 가요), 태그 버튼은 그 위(`position: relative; z-index`)에 둬요.
  - 마우스를 올렸을 때 모양(`a.card:hover`)은 새 카드에도 똑같이 줘요.
  - 키보드로는 제목 링크, 태그 버튼 순서로 가요.
- **목록 검색**
  - 검색창 placeholder는 "스터디 이름·목표·모집자·#해시태그"예요.
  - 로그인했고 태그가 있으면 검색창 아래에 "내 해시태그" 줄을 두고 내 태그 칩(`aria-pressed` = `tagInQuery`)을 보여 줘요. 누르면 넣거나 빼요.
  - 칩이나 카드 태그를 누르면 검색창의 값과 목록·개수가 바뀌어요. 카드 태그를 눌렀을 때는 검색창으로 포커스를 옮겨요.
  - 목록은 처음에 모든 스터디를 보여 줘요(제 판단). 빈 결과 문구는 지금 그대로예요("‘#7기’에 맞는 스터디가 없어요.").
- **스터디 상세**: 제목 근처에 스터디 태그를 모두 보여 줘요. 누르면 목록(`#/`)으로 가서 그 태그로 검색해요.
- **모집자의 신청 목록**: 신청자 이름 아래 작은 글씨(이미 있는 `small`)에 그 사람의 프로필 태그를 `#a #b`로 더해요.
- **내 스터디** 화면은 바꾸지 않아요.
- 색·간격·모서리는 Montage 토큰과 `style.css`의 별칭만 써요. 태그 버튼은 이미 있는 `.tag`·`.chip` 모양을 살려요.

- 태그 칩·입력칸의 정확한 간격과 줄바꿈 모양(Montage 토큰 안에서).

- 카드 태그 버튼의 크기(터치 대상은 지금 `.chip` 기준을 따라요).
